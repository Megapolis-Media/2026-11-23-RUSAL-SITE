# Выкладка на rusal.knzteam.ru

1. Владелец сливает PR из `dev` в `master` через merge commit.
2. Workflow **Deploy RUSAL production** ожидает подтверждения владельца в GitHub environment `production`. Он принимает только ветку `master`. При необходимости повторного выпуска запустите workflow вручную с этой ветки.
3. Ключ в `DEPLOY_SSH_KEY` открывает единственную команду выкладки. `DEPLOY_SSH_KNOWN_HOSTS` содержит проверенный публичный ключ хоста. Скрипт на сервере собирает образ из точного SHA на вершине `master`. После запуска он проверяет `/api/config`, а workflow повторяет проверку по публичному HTTPS.

Файлы сервера находятся в `/srv/rusal-fm`. Контейнер слушает `127.0.0.1:18178`. Nginx использует отдельный виртуальный хост и сертификат Certbot. `runtime.env` хранит настройки и секреты, а `data/rusal.sqlite` сохраняется при замене контейнера. Перед заменой скрипт останавливает прежний контейнер и копирует данные в `backups/`. Если проверка нового контейнера завершается ошибкой, скрипт возвращает прежний образ с существующими данными. Файл `.release` содержит SHA последней успешной выкладки.

Конфигурации из этого каталога устанавливает администратор сервера. Для HTTPS используйте Certbot с webroot `/var/www/rusal-acme`, а затем проверьте конфигурацию Nginx и перечитайте её. Время эфира и настройки Facecast, согласия и политики задаются в `runtime.env`. Значения переменных описаны в [README проекта](../README.md).
